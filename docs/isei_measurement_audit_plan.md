# ISEI Measurement Audit Plan

This document was written before Stage 05 was run and is kept as a record of the planned audit. The final implementation is documented in [`replication_audit.md`](replication_audit.md).

## Purpose

The historical reproduction in Stages 01 to 04 is frozen at `v1.0-original-reproduction`.

The next stage examines the ISCO-08 to ISEI-08 conversion used in the submitted dissertation. This is a measurement audit. No revised regression models will be estimated until the occupational-status measure has been checked.

## Historical baseline

Stage 03 reproduced the ISEI variable generated by the submitted SPSS workflow.

Among 1,674 respondents with a valid current or recent occupation, the historical mapping assigns an ISEI score to 1,670. Four cases with ISCO code 1000 remain unmapped.

All four unmapped cases are urban-origin bachelor graduates under the historical coding.

After the historical origin and parental-education requirements are applied, the pre-ISEI core contains 1,650 respondents and the submitted analytic sample contains 1,646.

These quantities are historical anchors. They are not targets for the revised mapping.

If the revised mapping adds only the four previously unmapped cases and does not lose any cases that were historically mapped, the resulting sample would contain 1,650 respondents, including 932 urban-origin respondents and 810 bachelor graduates. These figures are conditional diagnostics, not programmed success criteria.

## Revised mappings

Two documented mappings will be compared.

The primary revised mapping is `ISCO08ConveRsions::isco08toisei08`, which implements the SPSS-syntax version of the ISCO-08 to ISEI-08 conversion.

`ISCO08ConveRsions::isco08toisei08_2`, based on the alternative overview-table version, will be used as a measurement sensitivity check.

The two versions are not assumed to be equivalent.

## Code representation

CGSS occupational codes are stored numerically. This removes leading zeroes from codes such as 0100 and 0310.

A preliminary representation test showed that the conversion functions do not map the strings `100`, `110`, or `310`, while the canonical four-character forms `0100`, `0110`, and `0310` are mapped.

Stage 05 will therefore convert valid numeric occupational codes to canonical four-character strings before either revised mapping is applied.

The conversion functions will be evaluated once for each unique occupational code. Stage 05 will require every single-code call to return exactly one value. The resulting code-level mapping will then be matched back to respondents.

## Preliminary crosswalk check

A small set of occupational codes was examined before the full-sample audit.

Both revised mappings covered the aggregate codes included in this check, but some assigned scores differed substantially. For example, the syntax and overview mappings assigned 75.54 and 63 respectively to code 2300, and 68.88 and 56 to code 2350.

The syntax mapping also returns scores with greater numerical precision than the integer-valued historical mapping used in the dissertation.

These checks show that the sensitivity analysis may concern score assignment as well as coverage. They do not establish the size or direction of the full-sample effect.

## Evidence from earlier development versions

An earlier development version of the SPSS analysis provides additional evidence that occupational-status coding can matter for model estimates.

The development and final outputs use the same analytic sample of 1,646 respondents and reproduce the same age, parental-education, education-level, urban-rural and cohort distributions. The main substantive difference between these runs is the construction of ISEI.

In the earlier output, mean ISEI is 51.8688 with a standard deviation of 16.71182. In the final historical output, the mean is 51.9842 with a standard deviation of 16.34346.

The female coefficient in the corresponding adjusted model changes from 2.189 (SE = 0.799, p = .006) to 1.062 (SE = 0.774, p = .170).

The earlier ISEI construction contained a coding defect that allowed coarse fallback assignments to overwrite more detailed values. It is therefore not treated as a legitimate alternative crosswalk or as a sensitivity specification. The comparison is retained only as evidence that occupational-status coding can materially affect some estimates.

It does not provide a prediction about which coefficients will be most sensitive to the documented revised mapping.

## Audit sequence

Stage 05 will use the verified `stage3_dat` produced by Stage 03. It will not reconstruct the historical sample from the raw CGSS variables.

The audit will proceed in the following order.

First, occupational codes will be validated and converted to canonical four-character strings.

Second, the historical mapping will be checked for within-code uniqueness. A given occupational code must not correspond to multiple non-missing historical ISEI values.

Third, the two revised mappings will be calculated once at code level and checked for valid single-value returns.

Fourth, coverage will be measured separately for the historical, syntax and overview mappings. Both code-level and person-level coverage will be reported.

Fifth, transitions between mapping states will be examined in both directions. This includes historically missing codes that become mapped and historically mapped codes that become missing.

Sixth, score comparisons will be restricted to common support. Historical and revised scores will be compared at code level and person level, including signed changes, absolute changes, person-weighted changes and differences across ISCO major groups.

Only after these checks will the revised analytic sample boundary and its education and origin composition be calculated.

A revised sample size of 1,650 is plausible because the documented mappings cover code 1000 in the preliminary test. It is not programmed as an expected result or a success condition.

## Scope

Stage 05 will not estimate regression models.

It will not alter Stages 01 to 04 or the frozen `v1.0-original-reproduction` tag.

Respondent-level CGSS records will not be exported.

Parental occupational-status measures are outside the core audit. Their coverage may be examined separately after the respondent-level ISEI audit is complete.
